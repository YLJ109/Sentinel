# 运行与联调指南

面向部署与现场调试：环境准备、启动命令、凭据填写、能力自检、常见问题。
所有命令均在项目根目录 `CampusAntiBullying/` 下执行。

---

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10+ / Linux | 开发与验证在 Windows 完成 |
| Python | **3.11** | 后端；`.venv` 必须用这一个解释器 |
| Node.js | 18+ | 前端构建 |
| GPU（可选） | NVIDIA + CUDA 12.x 驱动 | 有则自动用 `cuda:0` 并开启 FP16；无则回退 CPU |
| 磁盘 | ≥ 2 GB | 模型权重约 20 MB，其余为取证录像/截图 |

> **重要**：后端必须使用项目自带的 `backend/.venv`。系统 Python 里常有残缺的 numpy/cv2
> （DLL 冲突），会表现为 `Numpy is not available`、模型预热失败、检测无结果。

---

## 2. 首次安装

### 后端

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env          # Linux: cp .env.example .env
```

### 前端

```powershell
cd frontend
npm install
```

---

## 3. 启动

### 后端（工作目录必须是 `backend`）

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

> `.env` 是**按当前工作目录**读取的，所以必须在 `backend/` 下启动；
> 数据目录、SQLite 路径则基于代码位置解析，与 cwd 无关。
>
> 需要局域网访问时把 `--host` 改为 `0.0.0.0`，并同步把 `.env` 里的
> `CAB_CORS_ORIGINS` 加上实际访问地址。

### 前端

```powershell
cd frontend
npm run dev                     # http://localhost:5173
```

生产构建：`npm run build` → 产物在 `frontend/dist`，交给 Nginx 托管即可。

### 默认账号

首次启动自动创建 `admin / admin123`。**登录后请立刻在「修改密码」里改掉。**

## 4. 凭据与关键配置（`backend/.env`）

完整可配置项见 `backend/.env.example`，下面只列必填/常调项。

### 4.1 云端语音识别凭据（不填则语音能力不可用）

支持三个 Provider，用 `CAB_ASR_PROVIDER` 切换：

| Provider | 值 | 需要什么 |
|---|---|---|
| **阿里云百炼（推荐）** | `dashscope` | 一个 API Key（`sk-` 开头） |
| 阿里云智能语音交互 NLS | `aliyun` | 项目 AppKey + Token 或 AccessKey |
| Vosk 本地离线兜底 | `vosk` | 无需凭据（首次会下载模型） |

#### 方式一：阿里云百炼（最简单）

百炼控制台 → API-KEY → 创建，把 `sk-` 开头的 Key 填进去即可：

```ini
CAB_SPEECH_ENABLED=true
CAB_ASR_PROVIDER=dashscope
CAB_DASHSCOPE_API_KEY=sk-xxxxxxxx
CAB_DASHSCOPE_ASR_MODEL=paraformer-realtime-v2
```

#### 方式二：智能语音交互 NLS

> **注意**：百炼与 NLS 是**两套完全不同的接入**，凭据不通用。百炼的 `sk-` API Key
> 拿到 NLS 网关会被拒（WebSocket 握手 HTTP 403）；反之 NLS 的 Token 也不能用于百炼。

| 变量 | 是否必填 | 从哪里拿 |
|---|---|---|
| `CAB_ALIYUN_NLS_APPKEY` | **必填** | 智能语音交互控制台 → 创建项目 → 项目 AppKey |
| `CAB_ALIYUN_ACCESS_KEY_ID` | 二选一 | RAM 访问控制 → 子账号 → 生成 AccessKey（建议只授 NLS 最小权限） |
| `CAB_ALIYUN_ACCESS_KEY_SECRET` | 二选一 | 同上 |
| `CAB_ALIYUN_NLS_TOKEN` | 二选一 | 由外部令牌服务签发的短期 Token（生产推荐） |

```ini
CAB_ASR_PROVIDER=aliyun
CAB_ALIYUN_NLS_APPKEY=<你的 AppKey>
CAB_ALIYUN_ACCESS_KEY_ID=<你的 AccessKeyId>
CAB_ALIYUN_ACCESS_KEY_SECRET=<你的 AccessKeySecret>
```

未配置时不会阻断启动：底部状态栏「语音识别」显示为不可用，鼠标悬停可见具体原因。

### 4.2 生产上线必改

```ini
CAB_ENV=production            # 触发安全校验
CAB_SECRET_KEY=<32 位以上随机串>
CAB_CORS_ORIGINS=["https://你的域名"]
CAB_MEDIA_COOKIE_SECURE=true  # HTTPS 部署
```

`CAB_ENV=production` 时若 `SECRET_KEY` 仍是默认值、或 CORS 含 `*`、或媒体 Cookie 未启用
Secure，服务会**拒绝启动**并把原因写进日志。

### 4.3 人脸检测

```ini
CAB_ENABLE_FACE=true
CAB_FACE_MODEL=                # 留空 = 用 OpenCV 自带 Haar 级联（离线可用）
```

想提升召回与准确率：下载开源 YOLO 人脸权重（如 `yolov8n-face.pt`）放进 `backend/models/`，
再把 `CAB_FACE_MODEL=yolov8n-face.pt`，重启后底部状态栏「人脸检测」会从
`OpenCV 级联` 变为 `YOLO 人脸模型`。

> 本系统只做**人脸定位**（画框 + 计数），不做人脸识别、不比对、不存储生物特征。

## 5. 能力自检

| 想确认什么 | 命令 |
|---|---|
| 云端语音整链路（鉴权→识别→关键词） | `python scripts/check_asr.py --wav asr_check.wav` |
| 行为识别精确率/召回率/F1 | `python scripts/evaluate.py --manifest samples/manifest.csv --out report.json` |
| 训练专用行为模型（吸烟/暴力） | `python scripts/train_behavior.py --epochs 100` |

Windows 下用 `.\.venv\Scripts\python.exe scripts\xxx.py ...`。

### 5.1 语音自检

先用 Windows 自带中文语音合成一段测试音频，再跑自检：

```powershell
cd backend
powershell -c "Add-Type -AssemblyName System.Speech; $s = New-Object System.Speech.Synthesis.SpeechSynthesizer; $s.SelectVoice('Microsoft Huihui Desktop'); $f = New-Object System.Speech.AudioFormat.SpeechAudioFormatInfo(16000, [System.Speech.AudioFormat.AudioBitsPerSample]::Sixteen, [System.Speech.AudioFormat.AudioChannel]::Mono); $s.SetOutputToWaveFile('asr_check.wav', $f); $s.Speak('你再这样我就打你了。救命啊老师快来。'); $s.Dispose()"
.\.venv\Scripts\python.exe scripts\check_asr.py --wav asr_check.wav
```

退出码：`0` 全部通过；`1` 识别结果为空；`2` 配置或网络错误。

### 5.2 行为评测标注清单格式

CSV（带表头，UTF-8），`normal` 表示该片段不应产生任何行为：

```csv
path,label
samples/fall_01.mp4,fall
samples/fight_02.mp4,fight
samples/normal_corridor.mp4,normal
```

`label` 取值：`fall` / `fight` / `argue` / `smoke` / `crowd` / `normal`。

## 6. 当前能力清单（与底部状态栏一致）

| 能力 | 实现方式 | 依赖 |
|---|---|---|
| 人体检测 | YOLOv8-Pose 一次前向同时输出人体框 + 17 关键点 | `yolov8n-pose.pt` |
| 人体骨架 | COCO-17 关键点连线渲染（前端 canvas 叠加） | 同上 |
| 人脸检测 | OpenCV Haar 级联（可换 YOLO 人脸权重） | `opencv` |
| 跌倒检测 | 外接框长宽比 + 躯干倾角 + 头部塌陷，三证据 ≥2 且连续 5 帧 | 姿态模型 |
| 打架检测 | 双人中心距 + 手腕速度 + 抬手姿态 + 框交叠，连续 4 帧 | 姿态模型 |
| 吵架检测 | 持续贴近 + 双方直立 + 无剧烈挥臂，连续 10 帧 | 姿态模型 |
| 抽烟检测 | 手腕-鼻尖接近度 + 肘高于胯（姿态代理特征） | 建议训练专用模型 |
| 聚集检测 | 同帧人数 ≥ 4 | 人体检测 |
| 语音识别 | 阿里云百炼 Paraformer 实时流式（可切 NLS / Vosk 本地兜底） | `sk-` API Key |
| 关键词检测 | 词表 + 归一化编辑距离容错（3 字容 1、6 字容 2） | 内置词表 |

## 7. 常见问题

**Q：日志出现 `Numpy is not available` / 模型预热失败 / 检测一直没结果？**
用错了 Python。确认启动命令是 `.\.venv\Scripts\python.exe`，而不是系统 `python`。

**Q：`cv2` 导入报 DLL 错误？**
`opencv-python` 与 `opencv-python-headless` 装到同一目录会互相覆盖。修复：

```powershell
.\.venv\Scripts\python.exe -m pip uninstall -y opencv-python opencv-python-headless
.\.venv\Scripts\python.exe -m pip install --force-reinstall --no-deps opencv-python-headless==4.10.0.84
```

**Q：权重下载慢或失败？**
手动下载 `yolov8n.pt`、`yolov8n-pose.pt` 放到 `backend/models/` 即可，程序不会重复下载。

**Q：没有 GPU / 显存不够？**
`.env` 里设 `CAB_DEVICE=cpu`；显存紧张时把 `CAB_VIDEO_WORKER_CONCURRENCY` 保持为 `1`（串行）。

**Q：前端页面能开、接口全 404？**
后端没起来或端口不是 8000。`frontend/vite.config.js` 里 `/api`、`/data` 代理到
`http://localhost:8000`。

**Q：实时检测开着摄像头，但一个框都没有、底部显示「送检 0 次」？**
WebSocket 没连上。两处要检查：

1. **开发环境**：`vite.config.js` 的 `/api` 代理必须带 `ws: true`。
   应用的实时检测/语音链路走 `/api/ws/detect`、`/api/ws/audio`，缺少 `ws: true`
   时升级请求会被当普通 HTTP 转发，WS 永远建不起来，而且**前端不会报错**
   （表现就是画面在动、帧数在涨，但送检 0 次、没有任何检测框）。
2. **生产环境**：Nginx 反代 `/api/ws/` 必须转发升级头，否则同样连不上：

```nginx
location /api/ws/ {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
}
```

**Q：人脸检测一直 0 个？**
默认用 OpenCV Haar 级联，对**远处的小脸**召回偏低（最小边长取画面短边的 6%）。
把开源 YOLO 人脸权重放进 `backend/models/` 并配 `CAB_FACE_MODEL` 可以明显改善。

**Q：摄像头管理 / 点位态势墙里没有摄像头？**
本机摄像头数量由浏览器 `enumerateDevices()` 决定，且**不预置任何演示数据**。
点「扫描本机摄像头」并允许摄像头权限，即可拿到真实设备名称并同步。
未授权时浏览器会隐藏设备名称，页面会给出提示。
